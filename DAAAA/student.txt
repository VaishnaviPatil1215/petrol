    }

Line 1: Function declaration

uint256	Data type of roll number
rollno	Roll number parameter

What is memory?

In Solidity, memory is a temporary data location.

Here:
string memory name


means the name parameter is held in temporary memory while the function executes.

We use it because strings are dynamically sized data types, and Solidity requires a data location for them when used as function parameters.

For example, when we call:
addStudent("Rahul", 101)


The name "Rahul" is passed as a memory string and the roll number 101 is passed as a uint256.

Next block: For loop
for(uint i = 0; i < studentarr.length; i++) {


Before adding a student, we need to check whether the roll number already exists.

For that, we use a for loop.

A for loop is used to repeat a block of code until a specified condition becomes false.

Let's break it down:
Part	Meaning
uint i = 0	Initializes the counter at zero
i < studentarr.length	Continues while the counter is less than the array length
i++	Increases the counter by one

Why do we use a for loop?

To check all previously added student records one by one.

Example:

Suppose our array contains:
Index	Name	Roll Number
0	Rahul	101
1	Priya	102
2	Amit	103

If we want to add a student with roll number 104, the loop checks:
- First iteration: Is 101 equal to 104? No.
- Second iteration: Is 102 equal to 104? No.
- Third iteration: Is 103 equal to 104? No.
The loop finishes because no duplicate is found.

Next block: If condition
if(studentarr[i].rollno == rollno) {


Let's understand this carefully.
- if checks a condition.
- studentarr[i] accesses the student at the current index.
- .rollno accesses that student's roll number.
- == checks whether two values are equal.
- rollno is the new roll number entered by the user.
For example:
studentarr[0].rollno = 101
new rollno = 101


The condition becomes:
101 == 101


This is true.

Therefore, the code inside the if block executes.

Next line: revert()
revert("student with this roll no already exists");


What is revert()?

revert() stops the current transaction and reverses the changes made during that transaction.

It also displays the specified error message.

Example:

Suppose we already have:
Rahul → 101


Now we try to add:
Priya → 101


The contract checks the roll number and finds that 101 already exists.

Therefore, it executes:
revert("student with this roll no already exists");


The transaction fails, and Priya is not added.

Why do we use revert()?

To prevent duplicate student roll numbers.

Final line: Adding a student
studentarr.push(Student(name, rollno));


This is where the new student is actually added.

Let's break it down:
- studentarr is our array.
- push() adds a new element at the end of a dynamic array.
- Student(name, rollno) creates a new Student structure containing the supplied values.
Example:

We call:
addStudent("Rahul", 101)


Solidity creates:
Student("Rahul", 101)


Then:
studentarr.push(Student(name, rollno));


Adds it to the array.

Our array becomes:
Index 0:
    Name = Rahul
    Roll No = 101


If we add Priya:
Index 0: Rahul, 101
Index 1: Priya, 102

Block 9: Get Student By Index Function
function getStudentByIndex(uint idx) public view returns(Student memory) {

    require(idx < studentarr.length, "index out of bound");

    return studentarr[idx];
}


This function retrieves the details of a particular student using their array index.

First, understand what an index is.

What is an index?

An index represents the position of an element in an array.

In Solidity, array indexing starts from zero.

Example:
Index	Name	Roll Number
0	Rahul	101
1	Priya	102
2	Amit	103

Notice that Rahul is at index 0, not index 1.

Line 1:
function getStudentByIndex(uint idx) public view returns(Student memory)


Let's understand:
- getStudentByIndex() is the function name.
- uint idx accepts the index entered by the user.
- public allows external access.
- view means the function only reads data.
- returns(Student memory) means the function returns one Student structure.
Example:
getStudentByIndex(1)


Here, idx = 1.

We want to retrieve the student at index 1.

Next line: require()
require(idx < studentarr.length, "index out of bound");


What is require()?

require() checks whether a condition is true.

If the condition is false, the transaction or function call is reverted and the error message is displayed.

Here, we are checking:
idx < studentarr.length


This ensures that the requested index exists.

Example:

Suppose:
studentarr.length = 3


Valid indexes are:
0, 1, 2


Let's check:
Entered index	Condition	Result
0	0 < 3	Valid
1	1 < 3	Valid
2	2 < 3	Valid
3	3 < 3	Invalid
5	5 < 3	Invalid

If we enter 3, the contract displays:
index out of bound


Why do we use require()?

To prevent accessing an array element that does not exist.

Final line:
return studentarr[idx];


This returns the student record at the specified index.

Example:
getStudentByIndex(1)


Output:
Priya
102


Why do we use this function?

To retrieve a particular student's details without displaying the entire array.
Block 10: Fallback Function
fallback() external payable {

}


This is a special function in Solidity.

What is fallback()?

The fallback function is automatically executed when a contract receives a call that does not match any existing function.

It can also execute when the contract receives Ether along with non-empty, unmatched call data.

Let's understand each keyword:
Keyword	Meaning
fallback()	Special fallback function
external	Can be called from outside the contract
payable	Allows the function to receive Ether
{ }	Function body

Why do we use fallback()?

To handle unexpected or unmatched function calls and, in this case, allow Ether to be received with such calls.

Example:

Suppose someone sends a transaction to our contract with an unknown function selector.

Since no matching function exists, the fallback function can be executed.

Because we declared it as payable, it can accept Ether.

Important: Our fallback function has an empty body. It accepts the Ether but does not perform any student-data operation or record the amount in a separate variable.
Block 11: Receive Function
receive() external payable {

}


This is another special function in Solidity.

What is receive()?

The receive function is automatically executed when the contract receives Ether through a transaction with empty call data.

Let's understand each keyword:
Keyword	Meaning
receive()	Special function for receiving Ether
external	Can be called externally
payable	Allows Ether to be received
{ }	Function body

Why do we use receive()?

To allow someone to send Ether directly to the smart contract without calling a specific function.

Example:

Suppose someone sends 1 ETH directly to our contract address without including any function call data.

The receive function executes.

Difference between fallback() and receive():

This is an important viva question.
receive()	fallback()
Executes when Ether is received with empty calldata	Executes when no function matches the call
Requires external payable	Can be payable or non-payable
Used for direct Ether transfers	Handles unmatched calls and can receive Ether
Does not handle non-empty unmatched calldata	Handles non-empty unmatched calldata

Remember:
- Empty calldata + Ether → receive() is called if it exists.
- Unmatched non-empty calldata → fallback() is called.
- Empty calldata with no receive() → fallback() may be called if it exists.

11. Time and Space Complexity
Let's understand the complexity of our functions.

Let n represent the total number of students stored in the array.
Function	Time complexity	Explanation
addStudent()	O(n)	Checks all existing records for duplicates
getStudentsLength()	O(1)	Directly accesses array length
displayAllstudents()	O(n)	Returns all student records
getStudentByIndex()	O(1)	Directly accesses an array index
fallback()	O(1)	Empty function body
receive()	O(1)	Empty function body

Space complexity:
- Student array: O(n), because we store n student records.
- addStudent(): O(1) auxiliary space for the loop counter and parameters, excluding the new record's storage.
- displayAllstudents(): O(n) for the returned array.
- getStudentByIndex(): O(1) for the returned student structure, excluding variable-sized string content.
The contract's permanent storage grows as more students are added.

2. Why do we use Blockchain for student records?
Let's first understand the problem with a traditional system.

Suppose a college maintains student information in a centralized database.
- The database is managed by a central authority.
- The college controls access to the records.
- Records can potentially be modified by someone with sufficient permissions.
- Other institutions may need to contact the college to verify information.
Now imagine using blockchain.

Blockchain provides a distributed ledger where transactions are recorded and can be independently verified.

Advantages of using blockchain:
Advantage	Explanation
Transparency	Transactions can be verified on the blockchain.
Security	Cryptography helps protect blockchain records.
Immutability	Confirmed records are difficult to modify.
Decentralization	The system does not depend on one central database operator.
Traceability	Changes and transactions can be tracked.

For example, when a student record is added to our smart contract, the transaction is recorded on the blockchain.

However, blockchain is not automatically the best choice for every college database. Public blockchain records are visible, so sensitive student information should not be stored directly on a public blockchain. A real system would use privacy controls and often store only verification proofs or hashes on-chain.
3. What is Blockchain?







techinika.com


Blockchain is a distributed digital ledger that stores information in blocks connected to each other.

Think of it as a digital register.

For example:
- Block 1 contains Transaction 1.
- Block 2 contains Transaction 2.
- Block 3 contains Transaction 3.
Each block is connected to the previous block using cryptographic techniques.

Why do we need it in this practical?

Because we want to store student records using a decentralized blockchain-based system instead of demonstrating only a traditional database.
4. What is a Smart Contract?
A smart contract is a program stored and executed on a blockchain.

It automatically performs predefined operations when called and when the required conditions are satisfied.

Think of it like an automated agreement.

For example, in our practical:
- When we call addStudent(), the student is added.
- When we enter a duplicate roll number, the contract rejects it.
- When we call getStudentsLength(), it returns the number of students.
We have written these rules in Solidity.

Why do we need a smart contract?

To automate student record management according to predefined rules without depending on a central server to execute the contract logic.

Think of Solidity as Python or Java, but designed for smart contract development.

Why do we need Solidity?

Because we need a programming language to define the rules and operations of our smart contract.
6. What is Remix IDE?







medium.com


Remix IDE

Remix is a free, browser-based development environment used to write, compile, deploy and test Solidity smart contracts.

Website: Open Remix IDE

Think of it this way:

You use VS Code to write Python or Java programs.

Similarly, you use Remix IDE to write and test Solidity smart contracts.
Why do we need Remix?
Remix provides all the tools required to work with smart contracts in one place.
Remix feature	Why we need it
File Explorer	To create our StudentData.sol file
Code Editor	To write Solidity code
Solidity Compiler	To convert Solidity code into bytecode and ABI
Deploy & Run	To deploy and execute the contract

What is compilation?

Compilation means converting our Solidity source code into a form that the Ethereum Virtual Machine (EVM) can execute.

What is deployment?

Deployment means publishing our compiled smart contract to a blockchain by sending a contract creation transaction.

8. What is an Ethereum Test Network?
A test network, also called a testnet, is a blockchain network used to test smart contracts without using real cryptocurrency.

Examples:
- Sepolia
- Hoodi
Why do we need a test network?

Suppose we create a smart contract and accidentally write incorrect code.

If we deploy it on the Ethereum mainnet, deployment and transactions require real ETH.

Instead, we can deploy it on a testnet and use test ETH.

Advantages:
- No real money is required.
- We can test contract functions.
- We can identify errors.
- We can practise deployment.
9. What is MetaMask?









MetaMask

MetaMask is a cryptocurrency wallet used to connect to blockchain networks and interact with smart contracts.


Why do we need MetaMask?
- To create a blockchain wallet.
- To connect to Ethereum networks.
- To receive test ETH.
- To approve smart contract deployment.
- To approve transactions.
For example, when we deploy our StudentData contract on Sepolia, MetaMask can ask us to approve the deployment transaction.

Note: Remix also has a built-in Remix VM for local testing, so MetaMask is not compulsory for every Remix practical.
